STEP 7 — Generate secure codes
Don't generate codes like:
SKL26-0001
SKL26-0002
because people can easily guess them.
Generate random characters.
For example:
SKL26-A8K4-92PX
SKL26-T7M2-48QA
SKL26-R9F6-13LK
Use a cryptographically secure random generator in your backend.
Do not generate them using a spreadsheet formula and assume they are secure.

STEP 16 — Build the webhook
Create an endpoint such as:
/api/payment/webhook
The payment gateway sends information there.
Your server should verify:
1. Signature
Is this webhook genuinely from the gateway?
2. Payment status
Is it actually successful?
3. Amount
Does it equal the expected amount?
4. Payment ID
Has this payment already been processed?
If all checks pass:
CREATE COUPON

STEP 18 — Prevent race conditions
This matters when multiple people pay simultaneously.
Imagine:
Customer A → payment success
Customer B → payment success
Both systems try to obtain coupon 0005.
You must use a database transaction/atomic allocation so only one gets it.
Never implement:
Find next number
↓
Wait
↓
Save
without protection.
Otherwise two people could receive the same coupon.

One important recommendation
Don't start by generating the 1,000 coupon images. Generate the coupon codes and database structure first, then generate a coupon only after a verified payment. This prevents unused coupons, duplicate codes, and unnecessary storage.
